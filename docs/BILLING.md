# Биллинг, регистрация и поддержка

Коротко: компания и пилот создаются сами, тариф выбирается в кабинете, счёт
уходит на email, после оплаты подписка включается. Просрочка больше 7 дней
переводит учёт в режим только чтения на уровне БД. Поддержка — форма в
кабинете и публичная страница, письма уходят на altai.dx@gmail.com.

## Что уже работает

| Что | Где |
|---|---|
| Self-serve регистрация: email, пароль, компания → пилот 30 дней | `app/register`, `lib/billing/provision.ts` |
| Активация после подтверждения почты (если включено) | `app/welcome` |
| Тарифы, подписка, счета | `app/(dashboard)/dashboard/billing`, `lib/billing` |
| Оплата счёта: ссылка Freedom Pay или счёт на email | `lib/billing/freedompay.ts`, `lib/billing/invoices.ts` |

| Автопереходы статусов и напоминания | `app/api/cron/billing/route.ts` |
| Отметить оплату, отменить счёт, выдать пилот | `app/admin/billing` |

## Шаг 1. Применить миграцию

Файл: `supabase/migrations/059_billing_support_devices.sql`.
Применяется вручную в Supabase Dashboard → SQL Editor, целиком, один раз
(база общая для staging и production).

Что проверить после применения:

```sql
select code, monthly_price from public.plan_offers order by sort_order;
-- 4 строки: trial 0, start 14900, plant 29900, network 54900

select policyname, permissive from pg_policies
where tablename = 'materials' order by policyname;
-- три строки "billing gate: insert/update/delete" с permissive = false

select proname from pg_proc
where proname in ('billing_provision_signup', 'billing_mark_invoice_paid', 'company_can_write')
order by proname;
-- три функции на месте
```

Скрипт идемпотентный: повторный запуск обновляет каталог тарифов и
пересоздаёт политики, данные не трогает.

## Шаг 2. Переменные окружения (Vercel → Settings → Environment Variables)

```
CRON_SECRET=…                 # Vercel шлёт его в Authorization для /api/cron/billing
FREEDOMPAY_MERCHANT_ID=…      # из кабинета Freedom Pay
FREEDOMPAY_SECRET_KEY=…       # платёжный ключ мерчанта
FREEDOMPAY_TEST_MODE=1        # 1 — тестовые карты, 0 — живые деньги
BILLING_LEGAL_NAME=…          # реквизиты в письме со счётом
BILLING_BIN=…
BILLING_IBAN=…
BILLING_BANK=…
```

Без `FREEDOMPAY_*` интерфейс показывает «Выставить счёт»: счёт сохраняется,
письмо уходит, онлайн-оплата скрыта. Это рабочее состояние, но не полностью
автоматическое: оплату по банковскому переводу отмечает владелец платформы
в `/admin/billing`.

## Шаг 3. Эквайринг Freedom Pay

Что нужно от вас: договор эквайринга с Freedom Pay, merchant_id и платёжный
секретный ключ. После вставки ключей оплата включается без правок кода.

Как устроено:

1. `POST https://api.freedompay.kz/g2g/payment_page` — создаёт платёжную
   страницу, возвращает `pg_redirect_url`.
2. Клиент платит на стороне Freedom Pay, карточные данные до приложения
   не доходят.
3. Freedom Pay шлёт результат на `https://pulse.altaidynamics.kz/api/billing/fp-result`
   с подписью `pg_sig`. Подпись проверяется до любых действий.
4. Сверяются номер заказа и сумма, затем `billing_mark_invoice_paid()`
   идемпотентно отмечает счёт и продлевает подписку.

Подпись: `md5(метод;значения_по_алфавиту;секретный_ключ)`.
Вектор из документации проверяется юнит-тестом
`tests/unit/billing.spec.ts` (`payment;…;test_secret_key` →
`b7ccbf6b20dc8125c70aa4e21617a2c0`).

Живой платёж не проверялся: мерчант-договора пока нет. Первый тест — с
`FREEDOMPAY_TEST_MODE=1` и тестовой картой `4716047261941981` (без 3DS).
Если Freedom Pay вернёт `94031`, в `pg_error_description` будет имя
недостающего параметра — смотреть логи `createPaymentPage`.

Автопродление (рекуррентные списания) не включено: для него Freedom Pay
должен включить рекуррент у мерчанта. Пока каждый период — новый счёт,
напоминания уходят автоматически.

## Шаг 4. Подтверждение почты (Supabase)

По решению владельца вход не блокируется подтверждением. Чтобы убрать
лишний шаг после регистрации: Supabase → Authentication → Sign In / Providers
→ Email → выключить «Confirm email». Код работает в обоих режимах:

- подтверждение выключено → компания создаётся сразу, вход в кабинет;
- включено → письмо, переход по ссылке, `/welcome` создаёт компанию.

## Как считается биллинг

| Тариф | Цена/мес | WhatsApp |
|---|---|---|
| Пилот | 0 ₸, 30 дней | — |
| Старт | 14 900 ₸ | +14 900 ₸ |
| Завод | 29 900 ₸ | 1 номер включён |
| Сеть | 54 900 ₸ | 2 номера |

Год — 12 месяцев со скидкой 20%. Пользователи не ограничены — как в
`PLAN_PRODAZH_AD_PULSE.md` §7.1.

Статусы подписки: `trialing` → `active` → `past_due` (после конца периода) →
`blocked` (через 7 дней просрочки). `private.company_can_write()` пропускает
запись в `materials`, `material_transactions`, `production_plans`, пока статус
не `blocked` и просрочка не больше 7 дней. Компании без строки подписки
(созданные до миграции) пишут всегда — fail-open.

Cron `/api/cron/billing` (раз в день, 06:00 UTC): переходы статусов,
напоминание за 5 дней до конца пилота, письмо в день окончания, письмо
о просроченном счёте через 3 дня после срока. Идемпотентность — таблица
`billing_events.dedupe_key`.

## Поддержка

- В кабинете: «Поддержка» в меню пользователя → форма, ответ приходит на
  email автора (Reply-To в письме).
- Публично: `/support` — без входа.
- Письмо уходит на `altai.dx@gmail.com` через Resend; обращение сохраняется
  в `support_requests` даже если Resend недоступен (тогда в ответе честно
  написано, что письмо не ушло).
- Антиспам: скрытое поле-ловушка и лимит 3 обращения с одного email за 10 минут.

## Устройства входа

`/api/auth/session` вызывается один раз за сессию. Первая пара IP +
user-agent создаёт запись в `user_devices` и отправляет письмо «новый вход».
Список — в настройках, вкладка «Безопасность»; устройство можно забыть.
Не больше одного письма в 10 минут на аккаунт.

## Проверка

```bash
npm run test:unit     # 10 тестов биллинга: подпись FP, суммы, grace-период
npx tsc --noEmit
npm run build
```

Миграция проверена на временном PostgreSQL 17: провижининг идемпотентен,
оплата продлевает период один раз, гейт блокирует insert при `blocked` и
при просрочке > 7 дней, старые компании пишут без подписки.

## Ограничения

- Живой платёж Freedom Pay не проверен — нет мерчанта.
- Рекуррентных списаний нет: каждый период выставляется новый счёт.
- В ручном режиме оплату по переводу отмечает владелец платформы.
- Письма Supabase на free tier (2/час) касаются только встроенной почты;
  приглашения и биллинг идут через Resend.
